> 本文分享的是登录接口的常见测试思路与检查清单，相关能力仅供授权的安全测试与学习使用，请遵守当地法律法规

## 前言

登录接口几乎是每个 Web 应用的大门，权限验证、账户体系、会话管理都绕不开它，问题往往也最集中，下面把登录口常见的测试点整理成一条可复用的流程，从上手到越权逐步排查

## 一、信息收集

打接口之前先摸清底细，避免盲测

### 指纹识别

先对目标做指纹识别，判断是否存在已知的 nday 组件，比如 **Shiro**、各类 **CMS** 与 **OA 系统**等。命中熟悉的指纹后，可以直接用对应已知漏洞打，效率远高于手动猜。常用工具：`Wappalyzer`、`Ehole`、`whatweb` 等

### 前端与接口收集

1. 打开 `F12` 查看 JS，搜索 `api`、`http`、`https`、`get`、`post` 等关键字，能挖出一批隐藏的接口；
2. 配合浏览器插件如 `findsomething` 批量提取页面中的 URL 接口；
3. 把收集到的接口统一扔进浏览器或 `Burp` 里跑一遍，重点看是否存在**未授权访问**、**敏感信息泄露**

## 二、认证机制

### 弱口令

登录口先试常用弱口令（`admin/123456`、`admin/admin` 等），后台和测试账号往往最容易中招

### 用户名枚举

用 `Burp` 配合用户名字典进行爆破，如果回显提示「用户名不存在」这类差异化信息，即可据此枚举出有效用户名，为进一步爆破或钓鱼做准备

### 短信轰炸

找回密码 / 注册界面抓包放到 `Repeater`，重放发送数据包，观察是否限制发送频率或次数，常见绕过方式：

- 并发发送，多线程同时触发；
- 号码前加 `+86` 或更换地区前缀；
- 号码中间插入空格等特殊字符

## 三、注入类漏洞

### SQL 注入

在数据包的参数值中插入单引号 `'`，观察返回是否报错或出现异常，判断是否存在 SQL 注入点；确认后用 `sqlmap` 等工具进一步利用

## 四、XSS

在用户名、邮箱、搜索等输入框或登录回显处，尝试 `javascript:alert(1)` 等 payload，测试是否存在反射型或存储型 XSS

## 五、越权

越权是最容易被忽略、也最严重的一类，分垂直和水平两种

### 垂直越权 / 接口越权

通过前面收集接口的方式，尝试对接口做字符串替换。比如登录接口长得像：

```
xxx.com/api/login
```

可以试着把 `login` 换成 `register`、`admin`、`user/delete` 等，看看是否存在未授权或越权操作

### 水平越权

先自行注册一个账号，登录后抓包，分析请求中的 `token`、`userId`、`session` 等参数是否可被篡改，排查因 token 泄露或参数未做归属校验导致的水平越权

## 六、逻辑漏洞

结合业务流程（密码找回、手机/邮箱验证、多因素绕过等）梳理整体逻辑，检查是否存在校验顺序错误、验证码绕过、密码重置任意绑定等逻辑问题

## 总结

按「信息收集 → 认证 → 注入 → XSS → 越权 → 逻辑漏洞」的顺序走下来，基本能覆盖登录口的大部分问题：

| 阶段 | 检查点 |
| --- | --- |
| 信息收集 | 指纹识别、JS/接口收集、未授权访问 |
| 认证机制 | 弱口令、用户名枚举、短信轰炸 |
| 注入类 | SQL 注入 |
| XSS | 登录回显/输入框弹窗测试 |
| 越权 | 接口替换（垂直）、token 篡改（水平） |
| 逻辑漏洞 | 找回密码/验证码/绑定等流程 |

实际测试中不必拘泥于顺序，命中可疑点就顺着往下钻，往往能连环突破
