## 1.引言

本文档旨在提供一份 Linux 系统的安全基线检查指南，帮助组织识别和解决潜在的安全问题，确保 Linux 系统的安全性和稳定性。
## 2.适用范围

适用于所有使用 Linux 操作系统的组织，作为编制安全审计、加固操作的参考依据。
## 3.缩略语

- PAM：Pluggable Authentication Modules
- SSH：Secure Shell
- Umask：User File Creation Mask
## 4.安全基线要求项命名规则

安全基线要求项是安全基线的最小单位，对应一个基本的可执行的安全规范明细。命名规则为：“安全基线 – 一级分类 – 二级分类 – 类型编号 – 明细编号”，例如：SBL-Linux-User-01-01，表示“安全基线 – Linux 类 – 用户管理 – 密码策略 – 密码复杂度”。
## 5.文档使用说明
### 5.1 适用环境

- RedHat 系统 Linux
### 5.2 操作指南

- 在配置系统基线测试之前，虚拟机一定要提前制作快照，配置测试期间尽量不要退出登录状态，以便出现差错的时候能够及时回退。
- 所有配置操作需谨慎执行，尤其是在生产环境中。
### 5.3 注意事项

- 修改关键文件（如 `/etc/passwd`、`/etc/shadow`）可能导致系统无法正常运行，请在测试环境中验证配置的正确性。
- 在修改系统配置文件后，及时备份相关文件，以便在出现问题时能够快速恢复。
## 6.安全配置要求
### 6.1 用户管理

|   |   |
|---|---|
|安全基线编号|SBL-Linux-User-01-01|
|安全基线名称|密码复杂度安全基线要求项|
|安全基线要求|设置用户密码复杂度策略，要求密码长度至少为 8 位，并包含多种字符类型|
|检测操作参考|查看 `/etc/pam.d/system-auth` 文件中 `password required pam_cracklib.so` 的配置|
|安全判定依据|`minlen` 值是否大于等于 8，是否启用了复杂度检查|
|参考操作|在 `/etc/pam.d/system-auth` 文件中添加或修改 `password required pam_cracklib.so try_first_pass minlen=8`|
|基线配置项重要度|高|
|操作风险评估|中|

|   |   |
|---|---|
|安全基线编号|SBL-Linux-User-01-02|
|安全基线名称|登录失败锁定机制安全基线要求项|
|安全基线要求|配置登录失败锁定机制，防止暴力破解|
|检测操作参考|查看 `/etc/pam.d/system-auth` 文件中 `auth required pam_tally.so` 的配置|
|安全判定依据|是否设置了 `deny` 和 `unlock_time` 参数|
|参考操作|在 `/etc/pam.d/system-auth` 文件中添加 `auth required pam_tally.so deny=5 unlock_time=600`|
|基线配置项重要度|高|
|操作风险评估|中|

|   |   |
|---|---|
|安全基线编号|SBL-Linux-User-01-03|
|安全基线名称|密码重复使用次数安全基线要求项|
|安全基线要求|限制用户重复使用密码次数|
|检测操作参考|查看 `/etc/pam.d/system-auth` 文件中 `password sufficient pam_unix.so` 的配置|
|安全判定依据|是否设置了 `remember` 参数|
|参考操作|在 `/etc/pam.d/system-auth` 文件中添加 `password sufficient pam_unix.so remember=5`|
